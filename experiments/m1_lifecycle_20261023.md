# M1 置信度与生命周期管理实验

## 已确认范围与实施计划

基线提交：`335e652`。用户确认独立实施、逐步验证，由用户手动执行 Git 提交，提交备注使用中文。保持现有联合网络、训练入口、配置和检查点不变；本实验不用 GT 坐标/身份推理，不用 128 维 M1 feature，不训练 M1。

本地验证环境：Python 3.10.13、NumPy 1.26.4、SciPy 1.10.1、PyTorch 2.6.0+cu126。
本模块推理为 NumPy/SciPy CPU 计算，不占用 CUDA 训练。

目标：优先减少误生轨迹和身份碎片，同时保留已有量测的定位能力。自主最多三条轨迹、已知人数、已知人数且确认身份不消亡三个条件分开报告。

### 先纠正上一阶段的语义

`max_missed=0` 是漏检立即删除，**不是目标不消亡**；已知人数也只是并发容量先验，并非数学上界。此前 F1=0.9154 对应“已知人数 + 漏检立即删除”，不能据此宣称固定生命周期效果。其原始 TP/FP/FN 数值保留。F1=0.8328→0.9032 的差为 0.0704。

### 文件与接口

- `original/my_track/lifecycle_tracker.py`：独立 NumPy 航迹管理器；`LifecycleTracker.update(positions[N,2], scores[N])` 返回坐标、轨迹 ID、置信度、当前观测标记；`reset()` 清除序列状态。`statistics` 返回建立、确认、删除数。
- `original/my_track/tracking_diagnostics.py`：独立逐帧一对一门控评估；GT 原槽号保持，不压缩身份。累计检测计数、GT 换预测 ID 次数、预测 ID 换 GT 次数、遮断后恢复片段、全局身份配对分数和纯预测 TP/FP。此诊断不冒充标准 MOTChallenge 实现。
- `original/my_track/gated_matching.py`：预测/评估共同使用的纯门控分配算法，只接收两组点及可选非负分数代价，不接收历史或 GT 身份。门内代价总和小于丢失一次匹配的 dummy 代价，保证先最大化有效配对数。
- `scripts/evaluate_m1_lifecycle.py`：同一遍缓存回放 simple baseline 与 lifecycle；按序列输出结果、参数、真实 sample ID 范围和数据形状；自主/已知人数/无消亡独立开关。结果写入用户指定 JSON，已有文件拒绝覆盖。
- `tests/my_track/test_lifecycle_tracker.py` 与 `test_tracking_diagnostics.py`：真实合成序列行为测试，不测试源码文本。

### 状态机及公式

高分候选先聚类（出生门限 0.96），低分（更新门限 0.8）仅作为离开主簇的补充，避免低分桥连接两个人。高分簇才允许新生，低分候选只能续接已确认轨迹。

`tentative → confirmed → coasting → 删除`；`coasting` 是已确认但本帧漏检。默认确认窗口复用 `HIST_LEN=20`，满窗口且至少 60% 帧有高分匹配后确认；不回填前缀输出。暂定轨迹漏检超过 2 帧删除。已确认状态先关联，再给暂定状态分配剩余高分候选。

运动门限内匈牙利匹配优先最大有效配对数，其次最小化 `distance/gate + 0.1*(1-score)`。速度以观测差分 EMA 更新（系数 0.2），每帧位移限制 0.2m；速度单位为 m/评估步，不使用现有可疑 DT=0.24 推算秒。漏检预测增量几何衰减，避免长时无约束外推。

第一版确认轨迹先关联高分簇、再用弱分候选补充（cascade）。合成反例发现：历史 x=1m 时会让 x=1.9m、score=.99 的假点抢走关联，压过 x=1.1m、score=.90 的合理量测。第二版改为：已确认轨迹对高分与弱分候选统一比较代价，暂定轨迹仍只关联剩余高分簇；保留 `association_policy='cascade'` 用于反例复现与完整对照。这是同一生命周期模块内的小范围修正，不更改已有训练网络。

观测置信度 `q ← 0.8*q + 0.2*score`；漏检 `q ← 0.95*q`。只有确认轨迹输出；漏检输出最多 2 帧且 `q>=0.5`；保留内部状态至 `HIST_LEN` 帧后删除。理想化“不消亡”模式保留确认 ID 直至序列结束，但超过输出预算停止输出预测点，不让无限外推造成虚假定位成功。新生 ID 单调增加，序列边界重置。

## 结果与操作记录

### 验证流程

1. 写三组测试，分别观察尚无对应模块时的导入失败；实现后完整回归 118 项通过。
2. 8 条记录各取前 40 帧 smoke，通过全部缓存适配；真实 out/conf/label 为 float32，shape 分别为 `[50,4]` / `[50,2]` / `[10,6]`。
3. 第一版完整验证 17,421 帧、32,332 个 GT 目标帧。全部记录 sample ID 最大相邻差为 1，没有跨序列拼接或帧索引跳跃。全部帧包含确认前缀。
4. 新增“近处弱量测不被远处高分假点压制”的测试，观察第一版输出 x=1.9m 而非 x=1.1m，确认失败；统一关联变体在此反例上通过。第二版完整对照证明整体效果退化，故最终默认恢复 cascade，joint 作为显式可选对照保留；不以一个合成案例的成功冒充全量收益。
5. 数值边界复核增加：五个 1m 配对必须优先于四个 0m 配对；空 GT 预测计 FP；观测位移 0.5m 被速度上限截为 0.2m 后，两次漏检位置为 0.7m/0.86m，长时预测位移有界。此阶段完整回归 122 项通过（67.595s）。最终策略复现参数与默认确定后，再跑完整回归：123 项通过（新增 30 项，14.197s），静态编译通过。时间差含并发任务与启动开销，未作速度收益声明。

自主生命周期 TP/FP/FN=26,959/1,589/5,373；旧 simple miss1 为 29,563/9,099/2,769。
纯预测点 TP/FP 从 886/3,328 变为 842/426，有效预测点占比从 21.0% 提至 66.4%。
这表明误报压制和身份碎片控制起作用，但新增启动延迟与保守出生也带来更多 FN。
不消亡模式虽只输出 14 个 ID，旧位置长期失效时会锁住容量，召回下降，不能作为
默认优化；其身份分数较高也不能掩盖缺失目标帧。

单帧高分聚类 F1=.8942，仍略高于第一版 lifecycle 的 .8856，但不含任何身份能力。
这些 MAE 只在各自门内匹配点上计算，不能把样本选择变化说成坐标纠偏收益；本模块没有学习坐标回归。

### 最终结论与下一步

保留自主 cascade + HIST_LEN 历史确认 + 弱量测续轨 + 有限预测输出作为独立参考实现。
不替换训练网络，不默认启用已知人数、不消亡、3 帧确认或统一关联；这些变体未显示
综合优势。相对较强的 simple miss0，本轮 F1 .8610→.8856、身份 F1 .1219→.3965；
相对 simple miss1，F1 .8328→.8856、GT 换 ID 1539→200、FP 9099→1589。

仍未解决：最困难三人序列 F1=.7489、身份 F1=.1481；当前确认/删除后重建依旧造成
启动延迟和碎片，长期失联时旧位置不可靠；纯坐标与置信度不能保证近距离交叉身份。
下一阶段优先做失联后的可靠再捕获、历史约束下的多人候选分离，不优先扩大网络或
重新调整训练损失。当前身份 F1 仅 .3965，不能宣称已达到稳定完整跟踪水平。
