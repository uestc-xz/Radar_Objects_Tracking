# my_track 网络结构细化条款

状态：架构讨论稿。本文记录已确认的需求约束与当前推荐方向；未确认的实现细节单独列出，不视为既定方案。当前阶段只细化设计，不修改业务代码。

## 1. 目标与范围

- 完善 `original/my_track` 的航迹管理与网络模块语义。
- 在冻结 M1 的前提下，利用其每帧候选位置、置信度和解码器特征，完成跨帧身份关联、多候选融合、漏检预测和坐标纠偏。
- 首要目标是维持序列内身份连续，尤其降低多目标交叉时的 ID 交换；之后再优化最终坐标误差。
- 本阶段不解冻或联合训练 M1。只有跟踪基线效果验证后，才另行评估是否解冻 M1。

## 2. 数据与序列约束

- 每个数据文件夹是一条独立记录，序列间不共享身份编号。
- 每条记录中的目标数固定为 1–3；记录期间没有真实目标进入或离开。遮挡或漏检不代表目标消亡。
- 同一记录的 GT 槽位顺序固定，可作为跨帧身份监督依据。
- 每条记录最多维护 3 个航迹槽位。确认后的身份在记录结束前保留，漏检不删除或重新编号。
- 序列边界重置全部航迹状态。

## 3. 已确认的 M1 输入约定

- 初始阶段冻结 M1。
- `IS_COLD=True`：直接读取 M1 缓存的坐标、置信度和特征，训练过程中跳过 M1 前向。
- `IS_COLD=False`：训练过程中运行冻结的 M1；M1 前向不参与梯度更新。
- 两种数据路径向跟踪模块提供一致的字段语义：候选坐标、M1 置信度和 128 维解码器特征。
- 每帧保留全部 50 个 query 候选，不在跟踪模块入口按固定置信度阈值硬删除。
- M1 置信度是可信但可被纠正的软证据。候选高置信度不代表必然正确；航迹历史、几何关系和其他候选可以降低其最终影响。
- M1 的 128 维向量按“解码器特征”理解。M1 未经专门身份区分训练，因此该特征仅作为可学习的辅助关联线索，不作为可靠身份标签或唯一判据。

## 4. 航迹启动、生命周期与输出

- 启动阶段使用 `HIST_LEN` 对应长度的多帧窗口积累候选证据，不再仅依赖首帧置信度 Top-K 初始化稳定身份。当前配置中的 `HIST_LEN` 为 20。
- 预热阶段允许输出暂定航迹；稳定 ID 在启动证据积累后建立。具体确认门槛留待训练后基于验证数据确定，不预先指定固定帧数或置信度阈值。
- 每条已确认航迹每帧输出一个最终坐标。无可靠候选支持时仍保留原 ID，并依据该航迹的历史状态预测位置。
- 输出需区分“量测支持”和“历史预测”状态，不能把预测点伪装成 M1 实测量测。
- M1 候选置信度与航迹最终置信度分开表示：前者描述候选本身的目标置信度，后者描述航迹模块对最终航迹点的可信程度。
- 连续漏检时航迹置信度逐步下降但 ID 保留；可信候选重新出现后可恢复置信度并修正位置。

## 5. 逐帧联合关联与位置生成

- 同一帧的候选集合和最多 3 条航迹状态由统一的联合跟踪过程比较，利用航迹间信息协助避免 ID 交换。
- 航迹之间可交换相对位置、运动趋势和观测状态等判断线索，但不得将不同身份的最终坐标混成一条航迹；每个 ID 独立输出。
- 单个 M1 候选每帧最多支持一个航迹或被判为杂波；一个航迹允许融合多个候选，也允许当前帧没有候选支持。
- 关联需结合候选位置、M1 置信度、解码器特征、航迹历史及其他航迹状态。高置信候选与时序或多目标关系明显冲突时，可以降低其影响。
- 允许多个关联候选融合成一个航迹点，不限定为取最高分候选。
- 最终点由关联候选融合结果与历史预测共同形成，并由坐标纠偏模块输出修正量。最终坐标可以超出候选坐标的范围，以便纠正共同偏差。
- 无可靠候选时根据航迹历史状态预测位置，而不是简单复制上一帧位置。
- 每帧最终航迹点使用对应 ID 的 GT 位置监督；位置回归损失采用 Smooth L1。具体损失权重和辅助损失尚待设计确认。

## 6. 跨帧身份训练与评价

- 训练时按整条记录建立固定的航迹槽位到 GT 身份映射，并跨帧沿用；不能每帧独立重做身份匹配，否则会把 ID 交换掩盖成合法重排。
- 训练的关联监督和最终位置监督必须使用相同的跨帧身份映射。
- 评估时以序列级身份交换/连续性为首要指标，以最终坐标误差为次要指标；漏检后是否维持同一 ID 也需单独检查。
- 具体指标名称、统计口径、验证集选择及阈值选择流程留待详细架构与实验计划阶段确定。

## 7. 推荐模块职责

```text
冻结 M1 或 M1 缓存
    -> 候选集合（50 个坐标、置信度、解码器特征）
    -> 联合跟踪器（候选-航迹关联、航迹间上下文、多候选融合）
    -> 航迹预测与坐标纠偏
    -> 每条已确认航迹的 ID、最终坐标、航迹置信度、观测/预测状态
    -> 更新航迹状态库
```

- **M1 输入适配**：统一缓存与在线冻结前向的数据接口，不承担跟踪关联策略。
- **候选集合**：保留 M1 原始置信度和解码器特征，提供本帧候选信息。
- **航迹状态库**：保存序列内稳定 ID、历史运动状态、特征摘要、漏检计数及航迹置信度；不负责选择 M1 候选。
- **联合跟踪器**：一次考虑所有候选与航迹，计算可供全局竞争的关联证据，并利用航迹间上下文。
- **位置生成/纠偏头**：融合候选与预测状态，回归最终航迹点；输出航迹级置信度及观测/预测状态。
- **训练与评估层**：实现固定的序列级身份监督、最终坐标回归及身份优先的评价报告。

- 沿用项目现有 Python、PyTorch 和模块化组织，不进行与跟踪目标无关的重构。
- 新模块使用清晰的中文模块说明，说明职责、输入/输出、关键张量 shape、坐标语义和状态约束。
- 公共前向接口的文档说明张量维度、字段含义、设备/批次假设及训练/推理差异。
- 注释说明非显然的决策理由、约束或梯度/状态处理原因；避免逐行复述代码。
- 对状态变更、关联约束、空槽处理和序列边界添加针对性测试；通过运行结果验证后再更新状态记录。

## 9. 待细化事项

- 启动窗口内如何形成暂定轨迹假设、如何在预热结束时建立稳定槽位，以及 ID 数值在记录内的初始化规则。
- 联合跟踪器采用的具体交互结构（例如候选-航迹交叉注意力、集合编码或其他轻量结构）及输入特征组织。
- 候选到航迹/杂波的关联分数、全局互斥约束和多候选融合权重的具体实现。
- 漏检状态下的预测和航迹置信度衰减/恢复公式或可学习实现。
- 跨帧关联损失、位置 Smooth L1、置信度损失之间的组合及权重选择方式。
- 训练窗口如何保留跨窗口身份监督与历史状态；长序列验证/测试如何完整回放。
- 使用验证数据确定启动确认门槛，并定义身份交换、漏检保持、坐标误差和置信度的报告指标。
- 是否需要候选丢弃、坐标扰动或高置信杂波等训练增强，需先检查现有 M1 输出统计再决定。
