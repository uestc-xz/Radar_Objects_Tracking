# my_track 网络结构细化条款

状态：实现规格 v1，代码与合成验证已完成。本文将已确认的用户约束与本轮工程默认值分开记录。默认阈值和损失权重仍需用训练/验证数据校准。M1 在跟踪基线通过验证前保持冻结。

## 1. 目标和边界

- 在 `original/my_track` 中建立语义清楚的联合航迹模块，融合 M1 候选、M1 分数、解码器特征和历史状态。
- 优先维护序列内身份连续性，再优化最终坐标误差；漏检/遮挡不得导致已确认 ID 删除或重新编号。
- `IS_COLD=True` 只读取 M1 缓存；`IS_COLD=False` 运行冻结且 `eval()` 的 M1。两路进入跟踪器后使用相同的 `[坐标, 分数, 特征]` 量测接口。
- 本阶段不解冻 M1、不启动全量训练、不覆盖已有 `original/my_track/runs/` 结果。

## 2. 数据、身份与坐标约束

- 每个文件夹是一条独立记录，每条记录最多 3 个目标；记录中目标不消亡，GT 三槽顺序在记录内代表固定身份。
- 序列边界重置状态；训练滑窗边界也重置状态，但始终使用数据原有固定 GT 槽位监督，不逐帧 Hungarian 重排。
- 坐标使用米制 `(x,y)`。GT `(0,0)` 表示空槽；不额外叠加 y 偏移。
- `HIST_LEN` 同时作为历史长度和身份确认预热长度，复用配置中的 20。
- M1 每帧 50 个 query 全部输入跟踪器。M1 score 是可纠正的软证据，不做输入门控；128 维 decoder feature 是辅助关联信息，不假设它具有身份判别保证。

## 3. 状态语义

- `initialized`：该槽已有至少一次量测支持或有效状态历史；可为暂定航迹。
- `confirmed`：稳定 ID 已对外固定；确认后在该记录剩余时段单调保持为真。
- `observed`：当前帧是否由至少一个 M1 候选支持。它与 `confirmed` 独立，缺测时仍可输出历史预测。
- `miss`：连续未观测帧数；漏检时增长，观测时归零。航迹置信度漏检时按 `MISS_CONFIDENCE_DECAY` 衰减，但不删除身份。
- 未确认的空槽可以被其他候选占用；已确认槽不重新分配给其他身份。GT 槽位固定监督保证这一约束。

## 4. 模块和接口

### M1 量测适配

`Measurements(pos[B,50,2], score[B,50], feat[B,50,128])`。`score` 由两类置信 logits 的 softmax 前景概率生成。适配器只统一字段和 shape，不读状态、不做关联、不筛 query。

### 联合跟踪器

- 候选 token：投影 `[x,y,score,feat]` 至 `d_model=128`。
- 航迹 token：GRU 编码 `[B,3,HIST_LEN,4]` 历史，并融合特征摘要、置信度、初始化/确认/漏检状态和槽位 embedding。
- 候选与航迹 token 合并，经 2 层、4 头 Transformer Encoder 做集合上下文交互；航迹之间因此能交换相对位置和运动线索。
- 每个候选输出 4 类关联 logits：杂波及三个固定槽位。前向用 straight-through hard argmax：一个候选最多归属一个槽位，但单槽可融合多个候选。
- 槽内融合用硬关联乘 M1 score 加权，归一化后形成融合位置/特征；空槽不把零向量解释成真实量测。
- 每槽根据最后位置和速度外推 `predicted_pos`。有候选支持时，融合预测与量测上下文并输出 gate 和无界二维 correction；无候选支持时 `final_pos=predicted_pos`，不应用量测 correction。
- 输出至少包含 `association_logits/assignments/assignment_onehot`、`fused_pos/fused_feat`、`predicted_pos/final_pos`、`observed`、`existence_prob` 和 `track_confidence`。

### 航迹状态库

`TrackBank` 保存三槽历史、特征摘要、航迹置信度、confirmed/initialized、缺测计数、存在概率滑窗和帧计数。每帧均写入最终预测/回归点以保持时间轴连续；只在完整 `HIST_LEN` 预热后，最近窗口平均存在概率达到 `CONFIRM_THRESHOLD` 时确认。没有航迹死亡逻辑。

### 训练损失

- 候选标签：距最近有效 GT 槽不超过 `ASSOC_LABEL_RADIUS_M` 时标对应固定槽，否则为杂波；允许同槽多正样本。
- 关联 CE 按样本分别对背景和正类归一化，再合并；没有正样本时只用有限的背景损失。
- 最终点位置损失只对非空 GT 槽计算 Smooth L1。
- 存在损失对三槽做 BCE；航迹质量损失以 `exp(-位置误差 / TRACK_QUALITY_SCALE_M)` 为有效槽软目标，空槽目标为 0。
- 总损失初值为 `2.0*L_assoc + 1.0*L_position + 0.25*L_existence + 0.1*L_confidence`，权重均可配置。

## 5. 冷/暖前向与训练/验证

- 训练保留 `WINDOW_SIZE/STRIDE` 滑窗；窗口开始 reset TrackBank，窗口所有帧（包括第一帧）都有逐槽损失。模型输出 detach 后写状态，避免跨整窗保留计算图。
- 暖路径 M1 以 `M1_BATCH_SIZE` 分块运行，始终 `no_grad()` 且冻结；冷路径不构造、不调用 M1。
- 验证按每个文件夹完整序列回放，状态只在记录边界 reset；逐帧读取数据/缓存以限制内存。
- `SHOW_PROGRESS=True` 时分别显示训练 batch 和验证序列进度，并在终端持续更新平均损失、学习率和累计验证帧数；每个 epoch 结束后仍输出完整指标汇总。
- 序列身份映射只在 warm-up 汇总位置上 Hungarian 初始化一次并固定。IDSW 统计追踪固定预测槽在后续帧中的 GT 身份所有权变化，不能重排输出。
- 报告 IDSW、固定槽映射下的平均欧氏点误差/RMSE、目标/目标帧覆盖率、预热后的漏检保持率，以及观测/预测点计数。未输出目标会通过覆盖率/未跟踪帧数显式体现，不能只看定位误差。确认阈值和标签半径需要验证扫描，未校准前不能作为最终结论。

## 6. 初始可配置默认值

| 配置 | 默认值 | 解释 |
|---|---:|---|
| `ASSOC_LABEL_RADIUS_M` | 1.0 m | 只用于关联正标签，不是推理门控 |
| `CONFIRM_THRESHOLD` | 0.5 | 可运行初值，需验证集扫描 |
| `MISS_CONFIDENCE_DECAY` | 0.95/帧 | 只衰减置信度，不影响 ID 保留 |
| `TRACK_QUALITY_SCALE_M` | 0.5 m | 航迹质量软目标的误差尺度 |
| `SHOW_PROGRESS` | `True` | 显示训练 batch 与验证序列进度 |
| Transformer | 2 层 / 4 头 / 128 维 / FFN 256 | 轻量三轨迹、五十候选交互 |

## 7. 代码与注释规范

- 沿用项目 Python/PyTorch 组织，不做无关重构；新增模块以中文模块说明描述职责、张量 shape、坐标单位及状态边界。
- 公共接口说明批次/设备/维度约定；注释解释状态单调性、straight-through 梯度、空槽处理等非显然约束，不逐行复述代码。
- 纯 CPU 合成测试覆盖形状、空槽、多人、多候选融合、漏检预测、确认与 reset；不访问用户数据或现有运行结果。

## 8. 验收清单

- M1 冻结边界正确，冷路径完全不调用 M1，暖路径无 M1 梯度。
- 50 个候选全部参与；每候选最多一个归属，多候选可落同槽。
- 最终点每帧监督，量测支持时 correction 可超出候选范围；漏检时严格采用历史预测。
- GT 固定槽监督、confirmed ID 单调保留、验证整条记录并只初始化一次槽映射。
- 单元/合成集成测试通过；真实数据正样本率、阈值扫描及正式训练留待后续实验，不在本轮伪称已验证。
