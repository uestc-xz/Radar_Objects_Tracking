## 设计与预先定义对照

新建 `TrackletIdentityRecovery`，输入旧管理器的 `TemporalFrameOutput`，只重命名 ID。
每个原始 ID 首次输出已经通过原有历史确认；不在首个孤立量测时重认身份。
保存最近观测端点、最近输出时间、原始 ID 所属关系。未输出的旧身份形成候选库，
不占旧管理器的活动容量，不输出虚构点。旧原始 ID 直接返回时保留映射。

1. `recovery_local`：自主，端点距离门 1m，记忆 HIST_LEN*50 步，歧义余量 .5m。
2. `recovery_reachable`：自主，距离门 `min(7.64, 1 + .02*gap)` m；记忆及歧义余量同上。
   .02m/步仅是可达范围假设（约 .8m/s），不是对时间戳或速度的拟合。
3. `recovery_known`：底层使用已知人数容量；同可达门，但已完整建立 N 个身份且仅有
   一个缺席身份和一个新片段时允许直接继承。此条依赖“固定人数、无真实消亡”，
   是明确的理想化条件，不作为自主能力。
4. 原始 `lifecycle`、`lifecycle_known` 为冻结对照，不改变其检测结果。

普通恢复要求门内最近配对，并且对“同一新片段的其他旧身份”及“同一旧身份的
其他新片段”均有至少 .5m 距离优势；有歧义则建立新 ID，宁可碎片也不强行交换。
有效原始 ID 映射也必须唯一：转让后旧原始片段再出现，不得与当前继承者同时输出同一 ID。
记忆过期只终止未知新片段的继承资格，已知原始片段返回仍可辨认自己的映射。
坐标、分数、observed 标记及其行顺序完全保持输入，允许用无 ID 指纹核对。

## 实际实现与验证经过

文件：`original/my_track/identity_recovery.py`，组合 `IdentityRecoveryTracker` 包装原有
`LifecycleTracker`，与裸身份后处理类分离。原生命周期源文件完全未改，评估器新增
三个显式变体和 `evidence_digest`（排除 ID 后的所有字段指纹）。
记忆按输入步计数，不冒用可疑的配置 DT；启动前缀及无输出帧完整计入。

14 项行为测试最初因模块缺失而导入失败；实现后通过。NPZ 缓存适配器测试先因
新变体不受支持失败，接入后通过；四帧样例中片段断开再恢复的 IDSW 从 1 到 0，检测不变。
把四帧 GT 全部替换为远处坐标后，恢复后的输出指纹仍完全相同。
首次完整 my_track 回归 138 项通过（14.403s），即旧 123 项加新 15 项。
CLI 拒绝覆盖测试会有预期的 argparse stderr，不是测试失败。
最终补齐标签扰动检查并复核：138 项通过（13.842s），四个新增/相关 Python 文件
`py_compile` 通过，`git diff --check` 通过。旧生命周期源文件和已有训练改动均未触碰。

真实缓存核查沿用 out/conf/label 的 float32 `[50,4]` / `[50,2]` / `[10,6]`，
取米制 xy 和稳定 softmax 前景概率，标签仅用于输出后的评估。八记录均为原始
完整顺序，17,421 帧、32,332 个 GT 目标帧；相邻 sample ID 最大差为 1。
每序列前 40 帧 smoke 总计 320 帧用于适配检查；这段没有重接回事件，不据此声称效果。

这里“恢复成功分配数”仅指通过规则、实际继承旧 ID 的次数，**不是 GT 核验正确重识别数**。
自主可达门相对原版身份 F1 增加 .09198，即 9.20 个百分点；检测没有任何改善或退化。
原版与两个自主变体均为 TP/FP/FN=26,959/1,589/5,373、匹配 MAE=.280508m；
已知人数两组均为 26,563/1,490/5,769、MAE=.279804m。全部组恢复片段数均为 610，
重命名身份不会填补缺帧。

三种恢复变体的逐序列 evidence_digest 与对应原版全部一致，包含坐标、置信度、
observed 标记、数组 shape 和行顺序；两种原版的完整 prediction_digest 及全部 metrics
也与 `lifecycle_full_20261023.json` 八序列逐项一致，排除无意改变基线的影响。

## 选择与下一步

本轮保留为**显式可选实验**，不替换原默认 `LifecycleTracker`。
验证了“检测已经固定时，片段间重接仍能改善长序列身份覆盖”，也暴露“空间可达不等于
身份可信”。下一步优先检查仍在持续输出的片段内部关联，区分真正的交叉串人和评估
距离匹配在近距离时的不稳定；之后再决定是否需要历史运动/量测特征证据。
本轮不继续在同一验证集上无限放宽门限或叠加规则。
高分聚类只读诊断不覆盖弱候选补充的过滤过程，不能据此排除所有候选生成问题。
