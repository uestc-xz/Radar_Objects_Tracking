## 设计

`HistoryMotionTracker` 复用原生命周期；基类只提取关联预测的受保护扩展点，默认返回
原本 `_predict(track, missed+1)`，必须以完整输出指纹证明默认未变。
新类记忆最近 HIST_LEN 个输入步骤内的真实观测坐标；无观测不加入预测点，删除状态时清理历史。
数据仅为 M1 xy/score，不用 128 维 feature 或 GT。

以最近观测时刻为 0，历史时刻为 `t_i<=0`：

`v = sum((t_i-mean(t))*(p_i-mean(p))) / sum((t_i-mean(t))²)`；
把 `||v||` 限制为原有 `max_step_m`，再令 `a=mean(p)-v*mean(t)`。
下一次关联预测为 `a + v * (1-d^gap)/(1-d)`，`d=prediction_decay`，`d=1` 时乘数为 gap。
时间单位为输入步骤，不用配置 DT 冒充物理速度。至少四个观测点才拟合，短历史回退原方法。
历史长度按输入步数而非观测数限制，跨长缺口不得把过旧位置混入当前拟合。

已观测输出仍为当前量测坐标，漏检输出仍使用原速度/衰减公式；历史预测只改变候选配对。
这不是坐标平滑模块，不把状态预测变化伪称量测纠偏。

## 第一轮完整结果及第二个局部假设

历史拟合完整四组结果已保存至 `original/my_track/runs/history_motion_full_20261023.json`。

发现 50 帧其配对与全体确认状态共同分配不同；其中 45 个活动状态在全体分配中无量测，
但独立分配时可匹配；另有两次活动状态的预测残差可降低 >.2m。
分序列差异帧为三人 9/26、双人 10/5；单人均无。该反事实不读取 GT，说明存在竞争，
不证明所有被活动状态抢回的点都是真实归属。

第二个实验 `recent_priority`：仅在 .5m 可信内门先给“上一帧有观测”的确认轨迹分配，
随后对剩余全部确认轨迹/量测继续原 1m 门匹配。高分阶段、弱分阶段分别如此，
未使用量测必须分别记账，禁止一份量测重复更新两条航迹。
远处量测不优先分配，避免强行把本应回归旧航迹的点抢给活动轨迹。
不改变坐标、速度、历史确认或生灭规则；此变体不启用历史拟合。
另列 `recent_priority_recovery`，恢复参数与上模块完全相同。
新类只支持 cascade，joint 请求显式拒绝，避免设置写为已启用但实际忽略。

第二轮预先定义完整四组：lifecycle、recovery_reachable、recent_priority、recent_priority_recovery。
继续同时报告 1m/.5m 门，完整指纹重现原基线；至少不增加 owner 切换才考虑推荐。

## 完整结果与最终选择

每一轮均为独立四组、八记录全量 17,421 帧；没有截掉启动确认阶段，共 32,332 个 GT
目标帧。全部用相同 M1 坐标/softmax 概率，不使用 feat、不调用 M1、不训练网络。
新增两组 smoke 每记录前 40 帧，仅核查读取和启动语义，不据此推断长时身份效果。
各记录 out/conf/label 均为 float32 `[50,4]` / `[50,2]` / `[10,6]`，sample ID 最大相邻差为 1。

  共新增 22 项。全套 my_track **160 项通过，14.016s**；七个相关 Python 文件编译通过，
  `git diff --check` 通过。测试日志的 1/1 epoch 来自已有合成训练回归，不是真实训练实验。
