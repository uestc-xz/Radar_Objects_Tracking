2. 关联损失：50 个候选应该分别属于谁？
首先根据原始 M1 候选坐标生成标签：找距离最近的非空 GT，距离 ≤ 1m 就标为该 GT 对应类别，否则标为杂波（这部分代码在哪里怎么写的？）。
允许多个候选属于同一个目标，不做一对一匹配。
每个候选的交叉熵是 −ln(预测给正确类别的概率)。对每个样本分别计算：
L_assoc = 0.5 × 前景候选平均交叉熵 + 0.5 × 背景候选平均交叉熵(这个0.5和config中配置的CLUTTER_WEIGHT是否冲突怎么算的)
只有前景或只有背景时，直接使用存在的那组均值，然后对 batch 平均。这样 48 个背景不会仅凭数量压过 2 个前景。
当前调用没有使用配置中的旧 CLUTTER_WEIGHT 调度。
见 [标签及关联损失 (line 44)](/E:/Jupyter/NewMOTR/original/my_track/association.py:44)。
3. 位置损失：最终航迹点离 GT 多远？
使用 SmoothL1(final_pos, gt)，只监督非空 GT 槽，不要求该槽已经确认，也不要求本帧有量测支持。槽位固定对应，不为降低损失重新排列身份。
单坐标误差为 d：
|d| < 1：损失 = 0.5 × d²
|d| ≥ 1：损失 = |d| − 0.5
训练时，每个时间步对 batch 内所有有效目标的 x、y 坐标取平均（这部分代码怎么写的怎么能对不同目标坐标取平均啊，这不对啊，）；
验证时，先在每帧有效目标内平均，再对真实帧等权平均。不同人数混合时，两种平均方式有区别。它不是日志里的 MAE。
见 [位置损失 (line 172)](/E:/Jupyter/NewMOTR/original/my_track/association.py:172)。
4. 存在性和航迹置信度：分别监督什么？
存在性监督“这个固定槽有没有真实目标”：非空 GT 标签为 1，空槽为 0。对全部三个槽计算二元交叉熵，再平均（又要平均？为啥要平均）。
L_exist = mean[−y×ln(p) − (1−y)×ln(1−p)]
航迹置信度监督“当前最终点定位得好不好”，不是再学习一次 M1 的置信度：
有效槽质量标签 q = exp(−最终点到 GT 的欧氏距离 / 0.5m)
空槽质量标签 q = 0
L_conf = mean[SmoothL1(预测航迹置信度, q)]
生成 q 时坐标使用了 detach()，因此这项损失不会通过质量标签直接推动坐标变化。
见 [四项损失实现 (line 146)](/E:/Jupyter/NewMOTR/original/my_track/association.py:146)。
5. 四项怎么合起来？算一个例子
假设一帧只有一个目标：GT=(1,2)，最终点=(1.3,2.4)；50 个候选中 2 个前景，正确类概率均为 0.8，48 个背景正确类概率均为 0.9。
存在概率为 [0.8,0.1,0.1]，航迹置信度为 [0.6,0.1,0.1]。
子损失	计算	结果
关联	0.5×(−ln0.8−ln0.9)	0.164252
位置	(0.5×0.3²＋0.5×0.4²)/2	0.062500
存在性	(−ln0.8−2×ln0.9)/3	0.144622----为啥除以3
置信度	距离为 0.5m，质量标签为 [e⁻¹,0,0]	0.012313


当前[加权配置 (line 62)](/E:/Jupyter/NewMOTR/original/my_track/config.py:62)为：
训练 = 2×关联 + 5×位置 + 0.25×存在性 + 0.1×置信度 = 0.678391
验证 = 2×关联 + 1×位置 + 0.25×存在性 + 0.1×置信度 = 0.428391
这组数已直接调用当前损失函数核算。日志中的 train_assoc/train_pos/assoc/pos 都是未加权子损失。
6. 为什么训练和验证仍可能差很多？
训练前 5 轮使用 GT 候选标签指导融合，随后教师比例逐步下降，第 15 轮起为零；教师提供的是候选归属，不是直接把 GT 坐标塞给回归头。关联 CE 从第一轮起一直训练。验证始终自主分配候选，GT 只用于事后计算损失和指标。
此外，训练每个 50 帧窗口清空历史，验证整条记录连续递推；状态写回时会 detach，不跨帧反传。窗口损失先按时间平均，epoch 再按实际帧数汇总。IDSW、MAE、coverage、oob 都只是评价指标，没有直接加入这四项训练损失。因此训练损失很低，并不直接说明自主闭环跟踪已经学好。
